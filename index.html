Why branchless exists

Some students have real, provable skills and still get blocked by an eligibility rule that only looks at their branch. A student with the right project experience can be shut out of a role while someone with nothing relevant is let in. That is frustrating, and it is unfair to both the student and the company.

Made by a student, for students. branchless ranks people by what they can show, not by the name of their branch.

3. Who is eligible

OpenCV verified: project and code OpenCV claimed: project, no code yet OpenCV listed on resume only OpenCV missing

Verified counts 100%, claimed 60%, listed only 30%. Skills only needs the minimum score and every starred must-have (at least claimed). Scores support a human decision; they never reject anyone. Code proof reads dependency files and repo languages, not README text. Submit is a demo and sends nothing.

How scoring works, and its limits

Scores come from keyword matching, so a skill pasted into a resume can be gamed. That is why "listed only" counts for just 30%. "Verified" needs both a project and public code, but it is still a signal, not proof of quality.

Automated ranking of candidates gets regulatory scrutiny in some places. Use these scores to prioritise a human review, never to reject anyone on their own.
