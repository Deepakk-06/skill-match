Why branchless exists

Some students have real, provable skills and still get blocked by an eligibility rule that only looks at their branch. A student with the right project experience can be shut out of a role while someone with nothing relevant is let in. That is frustrating, and it is unfair to both the student and the company.

Made by a student, for students. branchless ranks people by what they can show, not by the name of their branch.

Code proof reads dependency files and repo languages, not README text. Submit is a demo and sends nothing.

How scoring works, and its limits

Scores come from keyword matching, so a skill pasted into a resume can be gamed. That is why "listed only" counts for just 30%. "Claimed" needs the skill in a line that reads like real use — an action verb (built, deployed, trained…) or a genuinely detailed sentence — not just dropped into a tools list or a one-line "familiar with X" claim, and no single line can back up more than three skills at once, so a buzzword-stuffed bullet doesn't inflate the whole list. "Verified" needs both a project and public code, but it is still a signal, not proof of quality.

Automated ranking of candidates gets regulatory scrutiny in some places. Use these scores to prioritise a human review, never to reject anyone on their own.

Everything here — the skill matching and the scoring — runs as plain JavaScript in your browser. There's no paid API, no account, and no server involved, so it costs nothing to run and nothing is sent anywhere except a GitHub username, if you choose to add one.
